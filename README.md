# 규정 제·개정 에이전트

2026 공공 AI 대전환 챌린지 세션2 지정과제 · **과제③ 규정 제·개정 에이전트** 출품작

기관 규정집(규정·지침), 상위 법령·자치법규, 서식을 넣어 두면 규정을 새로 만들거나 고칠 때 유사 규정을 찾고 조문 초안·신구조문대비표·개정문을 쓰며, 조 번호 이동에 따른 인용 정정 대상(다른 규정·별표·서식)을 찾아 고치고, 기관의 규정관리규정에 따라 절차와 필요한 문서 세트를 안내하는 에이전트형 도구입니다.

## 접속 주소

실행하면 브라우저가 자동으로 열립니다. 열리지 않으면 **http://localhost:8103** 로 접속하세요.
(포트 변경: `python run.py --port 9000` 또는 `config.json`의 `port`)

## 실행 방법

필요한 것: Python 3.10 이상(3.10·3.11·3.13에서 구동 확인), 인터넷(처음 한 번 라이브러리 설치). 모델은 없어도 됩니다.

- **Windows**: `run.bat` 더블클릭 (처음 실행 때 실행 환경을 만들고 라이브러리를 설치한 뒤 시작)
- **macOS·Linux**: `./run.sh`
- **직접 실행**:
  ```
  pip install -r requirements.txt
  python run.py
  ```
- **실행 파일(.exe) 만들기(선택)**: Windows PC에서 `tools\build_exe.bat` 실행 → `dist\regulation-agent\regulation-agent.exe` (이 실행 파일 만들기는 Windows 환경에서 아직 시험하지 못했습니다)
- 종료: 실행 창에서 `Ctrl+C`

## 주요 기능

### 기본기능
- **제정**: 규정 이름·제정 목적·상위법 위임 조항을 주면 조문 체계(장·조)와 표준 조문 초안을 만듭니다. 숫자 자리는 【 】로 표시하고 유사 규정의 값을 미리 채웁니다. 사용료·감면·취소처럼 권리·의무에 관한 조는 상위 법령의 근거 조문을 찾아 붙입니다.
- **개정**: "대관 사용료 납부 기한을 7일에서 5일로 줄이고, 제8조 다음에 사용허가 취소에 관한 조문을 신설"처럼 개정 의도를 쓰면 개정 작업(글자 바꾸기·조 신설·삭제·항/호 추가·제목 변경·별표 수정)으로 바꿔 조문 수정안, **신구조문대비표**(바뀐 곳 밑줄), **개정문**("제8조제2항 중 "7일"을 "5일"로 한다.")을 만듭니다. 작업은 화면에서 고치거나 직접 추가할 수 있습니다.

### 선택기능(구동되는 수준으로 구현)
- **절차별 지원(에이전트)**: 한 문장으로 요청하면 대상 규정 찾기 → 개정안·대비표 → 인용 영향 → 절차 안내까지 차례로 처리합니다. 기관 규정관리규정에서 절차 단계·기간(예: 협의 5일 이상, 예고 10일 이상)·필요 문서를 읽어 건별로 진행 관리하고, 단계마다 필요한 문서를 바로 만듭니다.
- **조 번호 이동과 인용 정정**: 가지 번호(제8조의2)와 번호 이동 중 선택(기본값은 규정관리규정에서 읽음). 번호 이동 시 이 규정 안 인용, 다른 규정(「체육시설 운영 규정」 제9조 → 제10조), 별표 "(제10조 관련)", 서식 문구까지 찾아 정정안과 **서식 정정본 파일**을 만듭니다. 바뀐 조문을 인용하거나 같은 문구를 옮겨 적은 곳은 '확인 필요'로 알려 줍니다.
- **상위법 개정 영향 분석**: 상위 조례의 개정 전후 본문을 넣으면 조문을 비교하고(번호 이동·내용 변경·신설), 영향받는 기관 규정 조문·별표·서식을 찾아 개정 후보(인용 번호 정정, 기한 변경 반영, 감면 대상 목록 추가 등)를 제시하고 선택한 후보로 개정 건을 만듭니다.
- **유사 규정 검색·비교표, 제정 이유·개정 이유·부칙·행정예고문 초안**과 심의 안건, 관계부서 협의 요청서, 법무 검토 요청서(자동 점검 결과 포함), 공포문, 관계 규정·서식 정비 목록 — 한글(HWPX)·워드·마크다운, 전체 세트 ZIP
- **규정집 전체 점검**: 없는 조·삭제된 조 인용, 조·항·호 번호 빠짐, 규정명 표기 불일치, 정의한 용어와 다른 말(용어 묶음은 설정에서 기관별로 지정), 규정 사이 기한 충돌, 서식·별표 누락. 표기 문제는 바로 정정 개정 건으로 만듭니다.
- **법령 단위로 범위 확장**: 기관 규정뿐 아니라 조례·규칙·법령도 같은 방식으로 등록·개정·비교합니다(규정 종류에 맞춰 "이 조례는…" 등 표현 자동 조정). 법령 본문은 파일로 올리거나 붙여넣어 등록합니다.

## 작동 방법 (시연 순서)

1. 실행하면 브라우저가 열립니다(`http://localhost:8103`). 처음 실행 때 모의 규정집이 작업 폴더에 자동으로 복사됩니다.
2. **에이전트**에서 "개정 예시"를 누르고 "실행" — 처리 순서, 신구조문대비표, 개정문, 함께 고칠 곳, 다음 할 일이 나옵니다.
3. **개정**에서 같은 예시로 작업을 만든 뒤 번호 방식을 '번호 이동'으로 바꿔 보세요. 위임전결 규정·별표·서식의 인용 정정안이 나타납니다. "진행 건으로 등록"을 누릅니다.
4. **진행 관리**에서 절차 단계(입안 → 관계부서 협의 → 법무 검토 → 행정예고 → 심의 → 결재·공포 → 규정집 정비)를 따라 문서를 보고 내려받고, 단계를 완료 처리합니다. "전체 세트 내려받기"는 서식 정정본까지 ZIP으로 줍니다. "규정집에 반영"은 작업 폴더 사본에만 새 판을 저장하고 이전 판을 보관합니다.
5. **제정**에서 "예시 채우기" → "초안 만들기": 조문 초안, 위임 범위 검토, 유사 규정 비교표가 나옵니다.
6. **상위법 영향**에서 "시연용 개정본으로 분석": 조례 조문 이동(제7조 → 제8조 등)과 기한 변경이 기관 규정·별표·서식에 주는 영향 7곳이 나옵니다. "선택한 후보로 개정 건 만들기"를 누릅니다.
7. **전체 점검**에서 "점검하기": 일부러 넣어 둔 오류(없는 조 인용, 조 번호 빠짐, 규정명 표기, 용어 불일치, 여비 정산 기한 충돌 등)가 나옵니다.

발표·영상용으로 장면별 화면 조작과 설명을 정리한 대본은 [시연대본.md](시연대본.md)에 있습니다.

## 모델(LLM) 연결과 교체

- 모델 없이도 모든 기능이 규칙 기반으로 동작합니다. 모델을 연결하면 개정 의도를 개정 작업 목록으로 바꾸고(현행 조문에 없는 글자를 고치려는 제안은 버림), 제정 조문 본문을 다듬습니다. 조 제목·순서와 번호 이동·인용 정정·대비표 계산은 항상 규칙으로 처리해 결과가 모델에 따라 흔들리지 않습니다.
- 화면 오른쪽 위 **모델 배지**를 누르거나 `config.json`(예시: `config.example.json`)에서 바꿉니다. 코드 수정은 필요 없습니다.
- 지원 방식
  - `openai`: OpenAI 호환 API(`/v1/chat/completions`) — 행정안전부 AI 공통기반, vLLM, Ollama(`/v1`), LM Studio 등
  - `ollama`: Ollama 기본 API(`/api/chat`)
- 모델 설정 화면에서 **빠른 설정**(내 PC의 Ollama / AI 공통기반·vLLM)과 **모델 계열**을 고르고, **모델 목록 불러오기**로 서버에 실제 등록된 모델 이름을 받아 고를 수 있습니다.

### 행정안전부 AI 공통기반 지원(예정) 모델 연결

| 모델 계열 | 연결 방법 | 계열별 차이 처리(자동) |
|---|---|---|
| 젬마(Gemma, Google) | OpenAI 호환 또는 Ollama 예: `gemma3:4b` | system 역할을 받지 않는 서버면 지시문을 첫 질문에 합쳐 다시 요청 |
| 라마(Llama, Meta) | OpenAI 호환 또는 Ollama 예: `llama3.1:8b` | 없음(표준 형식) |
| GPT-OSS (OpenAI 공개 모델) | OpenAI 호환 또는 Ollama 예: `gpt-oss:20b` | 추론형: 토큰 한도를 늘리고, 생각만 하다 답이 비면 한도를 키워 다시 요청 |
| 엑사원(EXAONE, LG AI연구원) | OpenAI 호환 또는 Ollama 예: `exaone3.5:7.8b` | 답 앞의 생각 과정 태그(`<thought>`, `<think>`) 제거 |
| 하이퍼클로바X(HyperCLOVA X, 네이버) | OpenAI 호환(AI 공통기반·vLLM 등) | 생각 과정 태그 제거 |
| 솔라(Solar, 업스테이지) | OpenAI 호환 또는 Ollama 예: `solar-pro` | 없음(표준 형식) |

- 공통: JSON 출력 형식 지정(`response_format`)을 지원하지 않는 서버면 형식 지정 없이 다시 요청하고, 답에 섞인 설명·코드 블록을 걷어 내고 JSON만 읽습니다.
- 위 Ollama 이름은 예시입니다. AI 공통기반의 실제 주소와 모델 이름은 기관에서 안내받은 값을 쓰거나 **모델 목록 불러오기**로 확인하세요.
- 앱 코드는 `chat()`·`json()` 두 함수만 쓰므로 새 모델 계열이 추가돼도 앱 코드는 바뀌지 않습니다(`core/llm.py`의 `FAMILIES`에 한 줄 추가).
- 환경변수로도 바꿀 수 있습니다: `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`. API 키는 파일에 적지 않고 환경변수(기본 `LLM_API_KEY`)로만 읽습니다.
- 예) Ollama: `ollama pull gemma3:4b` 후 연결 방식 `openai`, 주소 `http://localhost:11434/v1`, 모델 `gemma3:4b`
- 모델이 낸 결과는 그대로 쓰지 않고 원문과 대조해 검증합니다(근거 위치·현행 조문에 실제로 있는지). 검증에 걸린 제안은 버리고 그 사실을 화면에 표시합니다. 모델 호출이 실패하면 규칙 기반 결과로 계속 진행합니다.

### 2종 이상 모델 검증 방법

- Windows: [Ollama](https://ollama.com/download)를 설치한 뒤 `모델검증.bat`을 더블클릭하면 젬마(`gemma3:4b`)와 엑사원(`exaone3.5:2.4b`)을 내려받아 주요 기능을 차례로 돌리고 `verify_report.md`를 만듭니다. 다른 모델은 `모델검증.bat llama3.1:8b gpt-oss:20b`처럼 이름을 붙여 실행합니다.
  - 모델 파일은 기본으로 C 드라이브(사용자 폴더 `.ollama`)에 저장됩니다. 다른 드라이브에 두려면 환경변수 `OLLAMA_MODELS`를 그 폴더로 지정하고 Ollama를 다시 시작하세요.
- 직접 실행:
```
python tools/verify_models.py --base-url http://localhost:11434/v1 --models gemma3:4b exaone3.5:2.4b
```
모델별·기능별 통과 여부와 걸린 시간을 `verify_report.md`로 남깁니다. `--mock`을 붙이면 가짜 모델 서버로 연결 경로와 계열별 응답 차이 처리(system 역할 거부, 생각 과정 태그, 추론형 빈 답)만 시험합니다(실제 모델 성능 검증이 아님).

> 현재 상태: 개발 환경에서는 실제 모델을 내려받을 수 없어 가짜 모델 서버로만 확인했습니다(5종 흉내, 전 항목 통과). 실제 모델 2종 검증은 `모델검증.bat`으로 실행해 보고서를 함께 제출하는 것을 권장합니다.

## 자료 사용과 원본 보호

- 함께 넣은 `sample_data/`는 가상의 **공공기관** 기준으로 지어낸 모의자료입니다. 실제 기관·인물·연락처와 관계없습니다. (`tools/samples_gyujeong.py`로 다시 만들 수 있습니다)
- 투입한 원본 파일은 읽기만 합니다. 규정집에 올린 파일은 작업 폴더(data/library)에 사본으로 저장하고, 개정 반영·서식 정정·상위 법령 교체 때마다 이전 판을 data/archive에 보관합니다.
- 작업 데이터와 산출물은 `data/` 폴더(설정 `data_dir` 또는 환경변수 `APP_DATA_DIR`로 변경)에만 저장합니다. 데이터베이스 설치가 필요 없습니다.

## 정식 활용(정보화사업) 이관 메모

- 파이썬 표준 라이브러리 웹 서버 + 바닐라 JS로 만들어 외부 프레임워크 의존이 적습니다. 기능 로직(`library.py, amend.py, enact.py, impact.py, lint.py, procedure.py, docs.py`)은 웹 계층과 분리되어 있어 다른 프레임워크로 옮기기 쉽습니다.
- 바꾸기 쉬운 연결 지점: 저장소(`core/store.py`, JSON 파일 → DB), 모델(`core/llm.py`, 설정만으로 교체), 문서 읽기(`core/loaders.py`), 문서 내보내기(`core/export.py`), 절차(기관 규정관리규정에서 자동으로 읽고, 없으면 일반 절차 사용)
- 로그인·권한은 시연 범위에서 단순화했습니다(정식 구축 시 기관 인증 연동 필요).

## 알려진 한계

- 개정 의도는 "A에서 B로", "'A'를 'B'로", "제○조 다음에 …에 관한 조문을 신설", "제○조 삭제", "제○조에 '…'를 호로 추가" 같은 문형을 규칙으로 읽습니다. 읽지 못한 문장은 화면에 알려 주며, 작업을 직접 추가하거나 모델을 연결해 보완합니다.
- 인용 정정은 조 단위까지 자동으로 합니다. 항·호 번호가 바뀌는 경우의 인용은 '확인 필요'로만 알려 줍니다.
- 신설 조문·제정 초안의 본문은 유사 조문이나 표준 조문 틀에서 가져온 초안이므로 담당자 검토가 필요합니다.
- 국가법령정보센터 Open API 연동은 넣지 않았습니다(법령 본문은 파일·붙여넣기로 등록). 정식 구축 때 `library.py`의 규정집 읽기 부분에 연계를 더하면 됩니다.
- 한글 HWP(5.0) 파일 읽기는 실제 HWP 파일로 시험하지 못했습니다(HWPX는 시험함).
